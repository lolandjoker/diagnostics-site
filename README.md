# diagnostics-site

Сайт эзотерической диагностики: бесплатный разбор по дате рождения (гороскоп, натальная карта, матрица судьбы), витрина консультантов, текстовая консультация по скрипту, курс.

## Что уже работает

- **Главная** (`/`): имя, дата рождения, согласие на обработку данных (с 18 лет).
- **Варианты диагностики**: в варианте — способ расчёта (число пути, архетип, знак зодиака, точки
  матрицы судьбы и др.) и для каждого значения короткий и полный текст. Новому человеку вариант
  достаётся случайно или по кругу и закрепляется; в админке — воронка по вариантам.
- **Разбор** (`/razbor/<id>`): короткая диагностика его варианта, дополнительные блоки и кнопка
  «Написать эксперту».
- **Чат с экспертом**: человек выбирает эксперта из тех, кто в сети; в чат сразу приходит полная
  диагностика с подписью «Подробный разбор». Эксперт работает в панели `/expert`: свои чаты, чаты
  коллег (только чтение), статус «в сети» (гаснет сам через 5 минут без панели), предложение продукта
  прямо в чате. Админ может ответить в любом чате — с подписью «Администратор». Сообщения
  обновляются опросом раз в 3 секунды.
- **Продукты** под разбором: у продукта может быть несколько цен, каждому человеку случайно
  показывается одна и дальше не меняется; в сводке видно, какая цена лучше продаёт.
- **Заказ** (`/zakaz/<id>`): почта и согласие с офертой. Пока платёжный сервис не подключён,
  оплату подтверждает админ; после этого уходит письмо с продуктом и показываются ссылки на мессенджеры.
- **Админка** (`/admin`): чаты, варианты диагностики, эксперты (профиль, фото, логин и пароль),
  продукты и цены, заказы, все тексты сайта, сводка.

## Стек

- TypeScript, монорепозиторий на pnpm
- `apps/web` — Next.js: публичные страницы и админка; база через Drizzle ORM, миграции в `apps/web/drizzle`
- `packages/engine` — расчёты: астрология, нумерология, матрица судьбы (чистые функции, тесты на эталонах)
- PostgreSQL 16, Redis 7, Docker Compose, Caddy

Изменили `apps/web/src/db/schema.ts` → `pnpm --filter @diag/web db:generate` создаст миграцию;
сайт применит её сам при запуске.

## Запуск для разработки

```bash
pnpm install
pnpm test        # тесты
pnpm lint        # линт
pnpm typecheck   # проверка типов
pnpm dev         # сайт на http://localhost:3000, админка — /admin
```

Docker для разработки не нужен: без `DATABASE_URL` сайт использует встроенный PostgreSQL (PGlite)
в `apps/web/.data`. Для входа в админку создайте `apps/web/.env.local`:

```
ADMIN_PASSWORD=любой-пароль-от-12-символов
SESSION_SECRET=любая-строка-от-32-символов-любая-строка
```

## Правила работы с кодом

- Основная ветка `main`; изменения — только через pull request.
- Одна задача — одна ветка `feat/<задача>`.
- Перед отправкой ветки: `pnpm lint && pnpm typecheck && pnpm test`.
- Секреты — только в `.env` (в `.gitignore`) и в GitHub Secrets. В код и историю не попадают.
- Изменения базы данных — только добавлять, не удалять и не переименовывать.
- Коммиты и описания PR — по-русски.
