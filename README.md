# diagnostics-site

Сайт эзотерической диагностики: бесплатный разбор по дате рождения (гороскоп, натальная карта, матрица судьбы), витрина консультантов, текстовая консультация по скрипту, курс.

## Что уже работает

- **Главная** (`/`): имя и дата рождения (с 18 лет) — дата вводится цифрами «ДД.ММ.ГГГГ», без календаря.
- **Варианты диагностики**: в варианте два текста, одинаковые для всех — от имени и даты рождения
  не зависят. Новому человеку вариант достаётся случайно или по кругу и закрепляется; в админке —
  воронка по вариантам.
- **Разбор** (`/razbor/<id>`): текст 1 его варианта и кнопка «Написать эксперту».
- **Чат с экспертом**: человек выбирает эксперта из тех, кто «в сети» или «занят» (занятому можно
  написать, он ответит позже); через 3 минуты в чат приходит
  текст 2 варианта с подписью «Подробный разбор». В чате — фото и статус эксперта, можно отправлять
  фото (JPEG, PNG, WebP до 5 МБ; с телефона снимок уменьшается перед отправкой). Эксперт работает в панели `/expert`: свои чаты, чаты
  коллег, статус «в сети» / «занят» / «не в сети» — держится, пока его не сменят (админ тоже может
  включить эксперта на срок или навсегда, отметить «занят»). Админ может ответить в любом чате — клиент видит такое сообщение от имени эксперта
  чата (подпись «Администратор» видят только эксперты и админ). Сообщения
  обновляются опросом раз в 3 секунды.
- **Рейтинг и отзывы**: у каждого эксперта рейтинг на карточке и в шапке чата — задаётся в админке
  (новому — случайный от 4,6 до 4,9), из отзывов не считается. Клиент оставляет отзыв в своём чате
  (звёзды и текст, один на чат); отзыв сразу виден на карточке эксперта с именем клиента. Раздел
  «Отзывы» в админке — скрыть или удалить.
- **Голосовые звонки в чате** — через интернет в браузере (WebRTC), без сотовой связи. Звонит
  эксперт или админ кнопкой над перепиской; клиент видит экран входящего звонка и может только
  попросить звонок («📞 звонок» в списке чатов). Итог звонка остаётся в чате. Звук идёт напрямую
  между браузерами или через свой TURN-сервер (сервис `turn`, временные пароли — `lib/calls.ts`).
- **Админка** (`/admin`): сводка, чаты, варианты диагностики (с воронкой до звонка), эксперты
  (профиль, фото, логин и пароль, статус), тексты сайта. Экспертов и варианты можно удалить
  (мягко: пропадают из списков и у клиентов, история и выданные тексты остаются). Эксперт со своим
  входом работает в админке с правами админа, кроме «Текстов сайта»; чаты у него — в его панели. Продукты, заказы и доп. блоки разбора
  убраны; их таблицы в базе остались (правило схемы), но не используются.

## Стек

- TypeScript, монорепозиторий на pnpm
- `apps/web` — Next.js: публичные страницы и админка; база через Drizzle ORM, миграции в `apps/web/drizzle`
- `packages/engine` — расчёты: астрология, нумерология, матрица судьбы (чистые функции, тесты на эталонах)
- PostgreSQL 16, Redis 7, Docker Compose, Caddy

Изменили `apps/web/src/db/schema.ts` → `pnpm --filter @diag/web db:generate` создаст миграцию;
сайт применит её сам при запуске.

## Запуск для разработки

```bash
pnpm install
pnpm test        # тесты
pnpm lint        # линт
pnpm typecheck   # проверка типов
pnpm dev         # сайт на http://localhost:3000, админка — /admin
```

Docker для разработки не нужен: без `DATABASE_URL` сайт использует встроенный PostgreSQL (PGlite)
в `apps/web/.data`. Для входа в админку создайте `apps/web/.env.local`:

```
ADMIN_PASSWORD=любой-пароль-от-12-символов
SESSION_SECRET=любая-строка-от-32-символов-любая-строка
```

## Правила работы с кодом

- Основная ветка `main`; изменения — только через pull request.
- Одна задача — одна ветка `feat/<задача>`.
- Перед отправкой ветки: `pnpm lint && pnpm typecheck && pnpm test`.
- Секреты — только в `.env` (в `.gitignore`) и в GitHub Secrets. В код и историю не попадают.
- Изменения базы данных — только добавлять, не удалять и не переименовывать.
- Коммиты и описания PR — по-русски.
