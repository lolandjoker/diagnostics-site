# Выкат на сервер — инструкция

Сайт: https://diagnostics-free.com · сервер 195.133.81.137 (Ubuntu, Timeweb).

## Как это работает

1. PR сливается в `main`.
2. GitHub запускает «Проверки» (линт, типы, тесты, сборка, Docker).
3. Если всё зелёное — автоматически запускается «Выкат на сервер»:
   - проверяет, что сервер подлинный (отпечаток ключа);
   - готовит сервер (повторно безопасно: что уже сделано — пропускается);
   - делает резервную копию базы;
   - собирает и запускает новую версию **внутри tmux** — обрыв связи не прервёт выкат;
   - если новая версия не поднялась — **сам возвращает предыдущую**;
   - одновременно идёт только один выкат; журналы контейнеров при сбое остаются на сервере, в публичный журнал GitHub не попадают;
   - проверяет сайт снаружи: HTTPS, ответ, заголовки безопасности, перенаправление с HTTP;
   - через **15 минут** проверяет ещё раз.
4. Список изменений простыми словами — на странице запуска в Actions (раздел Summary).

Ключ от сервера лежит только в GitHub Secrets (`SSH_PRIVATE_KEY`) и на Mac владельца.

## Что проверить после выката

- Actions → «Выкат на сервер» → последний запуск зелёный, оба шага: «Выкат» и «Проверка через 15 минут».
- https://diagnostics-free.com открывается, в адресной строке замок.
- С телефона тоже открывается.

## Если что-то пошло не так

| Что видно | Что делать |
| --- | --- |
| «Выкат» красный, но сайт работает | Новая версия не поднялась, автоматически вернулась предыдущая. Ничего не делать, Claude разберёт причину по журналу |
| Сайт не открывается | Actions → «Выкат на сервер» → **Run workflow** (ветка main) → `rollback` → Run. Вернётся предыдущая удачная версия; повторный откат идёт ещё на шаг назад |
| «На сервере есть ручные правки в коде» | Кто-то правил файлы на сервере. Выкат ничего не тронул. Написать Claude: решим, сохранить правку в git или убрать |
| «Отпечаток сервера не совпадает» | **Ничего не делать, сразу написать Claude.** Выкат остановлен: возможна подмена сервера или сервер переустановлен |
| Нужно посмотреть руками | На Mac: `ssh -i ~/.ssh/deploy_key root@195.133.81.137` → `/opt/diagnostics/state/deploy.sh status` |

## Админка

https://diagnostics-free.com/admin. Пароль создан на сервере при подготовке и лежит только там:

```bash
grep ^ADMIN_PASSWORD= /opt/diagnostics/app/.env
```

Сменить пароль: поправить строку в `/opt/diagnostics/app/.env` и перезапустить сайт —
`cd /opt/diagnostics/app && docker compose --project-name diagnostics up -d web`.

## Команды на сервере

Все долгие команды — внутри `tmux`, чтобы обрыв связи их не прерывал.

```bash
/opt/diagnostics/state/deploy.sh status      # что работает сейчас
/opt/diagnostics/state/deploy.sh rollback    # вернуть предыдущую версию
tmux ls                                      # идёт ли выкат прямо сейчас
tail -n 50 /opt/diagnostics/logs/*.log       # журналы выкатов и сбоев
ls -lh /opt/diagnostics/backups/             # резервные копии базы (последние 14)
```

## Где что лежит на сервере

| Путь | Что там |
| --- | --- |
| `/opt/diagnostics/app` | код сайта (git) |
| `/opt/diagnostics/app/.env` | пароль базы и домен; создан на сервере, в git не попадает |
| `/opt/diagnostics/backups` | резервные копии базы перед каждым выкатом |
| `/opt/diagnostics/logs` | журналы выкатов |
| `/opt/diagnostics/state` | история удачных выкатов (`history`, последняя строка — текущая версия) |

## Что сделано на сервере при подготовке

- Docker и Docker Compose; логи контейнеров — не больше 30 МБ на контейнер.
- Файрвол: открыты только SSH, HTTP (80), HTTPS (443). База и Redis наружу не открыты.
- Автоматические обновления безопасности Ubuntu.
- fail2ban: после 5 неудачных попыток входа за 10 минут адрес блокируется на час.
- Подкачка 2 ГБ — чтобы сборка не падала от нехватки памяти.
- Вход по паролю отключён ещё 19.10 — только по ключу.

## Защита ключа окружением production (рекомендуется, 3 минуты)

Сейчас ключ от сервера — общий секрет репозитория: его может получить запуск из любой ветки (это могут только люди с правом записи — сейчас владелец и Claude). Окружение `production` с правилом «только main» закрывает и это:

1. Settings → Environments → **production** (появится после первого выката) → Deployment branches and tags → **Selected branches** → Add rule → `main`.
2. Там же → Environment secrets → **Add secret** → имя `SSH_PRIVATE_KEY` → вставить ключ (на Mac: `pbcopy < ~/.ssh/deploy_key`, затем Cmd+V).
3. Settings → Secrets and variables → Actions → у репозиторного `SSH_PRIVATE_KEY` нажать корзину.
